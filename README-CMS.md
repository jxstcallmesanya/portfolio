# Управление галереей

Сайт читает список файлов из **`gallery.json`** в корне репозитория. Формат:

```json
{
  "auto": ["img/auto/1.webp", "img/auto/2.webp"],
  "people": ["img/people/1.webp"]
}
```

В интерфейсе Decap списки сохраняются в том же виде (массивы путей). Старый вариант с объектами `{ "image": "..." }` тоже поддерживается.

Порядок строк в массиве = порядок снимков в сетке.

---

## 1. Быстро без CMS (рекомендуется начать с этого)

1. Кладите новые файлы в `img/auto/` или `img/people/` (webp, jpg, png — как удобно).
2. В папке проекта выполните:

   ```bash
   npm run gallery:scan
   ```

3. Скрипт пересоберёт `gallery.json` по фактическим файлам (сортировка по имени, «естественная» для чисел: `1`, `2`, … `10`).
4. Закоммитьте изменения (`gallery.json` + новые картинки) и отправьте в GitHub — Vercel подхватит деплой.

Если папки пустые, скрипт подставит шаблонные пути `1.webp` … `49.webp` / `1.webp` … `15.webp` (как раньше по счётчику).

---

## 2. Decap CMS (веб-редактор в браузере)

Откройте на сайте: **`/admin/`** (например `https://portfolio-jxstcallmesanya.vercel.app/admin/`).

Чтобы **войти через GitHub** и сохранять правки в репозиторий, нужен **OAuth**. Без него кнопка входа не заработает — используйте вариант 1 выше или настройте OAuth.

### Шаги (кратко)

1. **GitHub → Settings → Developer settings → OAuth Apps → New OAuth App**  
   - **Authorization callback URL** зависит от того, какой прокси OAuth вы используете (см. ниже). Для типового прокси из документации Decap часто указывают URL вида `https://<ваш-прокси>/auth/callback` или из README выбранного прокси.

2. Разверните **OAuth-прокси** (Decap не хранит секреты в браузере; нужен небольшой сервер). Варианты:
   - готовые образы вроде [netlify-cms-github-oauth](https://github.com/vencax/netlify-cms-github-oauth) (подходит и для Vercel/Railway/Render — смотрите README проекта);
   - или следуйте [официальной документации Decap — GitHub backend](https://decapcms.org/docs/github-backend/).

3. В **`admin/config.yml`** у блока `backend` при необходимости добавьте поля `base_url` и `auth_endpoint` **так, как требует ваш прокси** (пример из документации Decap / README прокси).

4. В репозитории GitHub включите доступ приложения OAuth к репо (или используйте Personal Access Token только для прокси — по инструкции прокси).

5. После входа в `/admin` вы сможете:
   - загружать снимки в **Авто** / **Люди**;
   - менять порядок (перетаскивание в списке, если доступно в вашей версии UI);
   - сохранять — Decap создаст коммит в `main`, Vercel задеплоит сайт.

Файл репозитория в конфиге: `jxstcallmesanya/portfolio`. Если форк — поменяйте `repo:` в `admin/config.yml`.

---

## 3. Локальная проверка Decap без OAuth

Включите в `admin/config.yml` строку `local_backend: true`, установите зависимости и запустите [Decap proxy server](https://decapcms.org/docs/working-with-a-local-git-repository/) — удобно для отладки на компьютере. Перед пушем в прод верните `local_backend: false`.

---

## 4. Альтернативы «на будущее»

- **Cloudinary / Uploadcare** — хостинг картинок + API; фронт переписывается под URL из API.
- **Sanity / Contentful** — полноценная headless CMS, больше кода и зависимостей.
- Для только ваших правок часто достаточно **варианта 1** + редкий заход в `/admin` после настройки OAuth.
