# Управление галереей

Сайт читает список файлов из **`gallery.json`** в корне репозитория. Поддерживаются:

```json
{
  "auto": [
    "img/auto/1.webp",
    { "full": "img/auto/2.webp", "thumb": "img/auto/2-thumb.webp" }
  ],
  "people": [
    { "full": "img/people/1.webp", "thumb": "img/people/1.webp" }
  ]
}
```

Админ-панель на **`/admin`** дописывает пути в этот файл автоматически (см. **`README-ADMIN.md`**).

Порядок элементов в массиве = порядок снимков в сетке.

Для объектов можно дополнительно указать:
- `srcset` — строка responsive-источников;
- `sizes` — строка размеров для `srcset`;
- `width`/`height` — размеры для стабильного layout.

---

## 1. Быстро без CMS (рекомендуется начать с этого)

1. Кладите новые файлы в `img/auto/` или `img/people/` (webp, jpg, png — как удобно).
2. В папке проекта выполните:

   ```bash
   npm run gallery:scan
   ```

3. Скрипт пересоберёт `gallery.json` по фактическим файлам (сортировка по имени, «естественная» для чисел: `1`, `2`, … `10`, затем разворот — новые сверху).  
   Если рядом есть миниатюра `<имя>-thumb.webp`, в `thumb` будет записан её путь.
   Если рядом есть `img/<section>/thumbs/<filename>.webp`, он автоматически подставится как `thumb`.
4. Закоммитьте изменения (`gallery.json` + новые картинки) и отправьте в GitHub — Vercel подхватит деплой.

Если папки пустые, массивы в `gallery.json` будут пустыми — жёстких ограничений по количеству кадров больше нет, порядок полностью берётся из файла.

По умолчанию порядок на сайте — **новые сверху**:
- при загрузке через `/admin` новая запись добавляется в начало массива;
- `gallery:scan` также формирует массив в порядке от новых к старым.

Логика загрузки на сайте:
- в сетке загружается `thumb` (лёгкая миниатюра);
- при открытии в lightbox загружается `full` (оригинал).
